# 监听任务补齐内容间隔

在桌面端或手机端打开监听任务的“一键补齐”，检测到遗漏内容后，可同时填写补齐条数和内容间隔（秒）。

- 内容间隔由用户在每次补齐时手动设置，默认 60 秒，允许 1–86400 秒的整数。例如 300 秒表示 5 分钟。
- 首条直接进入发送队列；一条内容发送完成后，等待设定间隔再处理下一条。相册整体算一条内容，多目标分发完成后再开始计时。
- 不在首条之前或末条之后额外等待。被过滤或去重、未发送的内容不会重新开始间隔计时。
- 现有全局发送限流继续生效，因此实际发送间隔可能更长。补齐等待不会占用全局发送锁，不改变实时监听的发送节奏。
- 首页队列展示内容间隔等待原因和预计处理时间。提交失败时保留表单输入，可直接重试。
- 该设置只适用于本次补齐；没有新增数据库字段，也不需要数据库迁移。

接口：`POST /api/listener-tasks/{task_id}/catchup-latest`

```json
{ "background": true, "limit": 10, "interval_seconds": 300 }
```

同步和后台执行都使用 `interval_seconds`。省略该参数时默认 60 秒，非法值返回 422。原有任务归属检查和重复补齐保护保持不变。
