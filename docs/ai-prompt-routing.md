# AI 文案分析与分类提示词

## 使用方法

1. 在“AI 配置”中配置模型供应商。
2. 新增或编辑提示词，设置“适用类型”。内容为空时，可点击“填入内置提示词”后编辑。
3. 用“文案试写”输入源正文，检查分类、改写范围、匹配提示词、完整提示词和输出。试写使用已配置的 AI，产生正常调用费用，不发送到频道。
4. 在克隆任务或监听任务的 AI 改写设置中，将“提示词模式”切换为“自动分析并匹配提示词”，保存。

旧任务默认仍是“固定提示词”，继续按原有方式运行。自动模式不会使用任务固定选择的提示词；切回固定模式后保留原选择。

## 匹配规则

### 通用规则只维护一处

在“AI 配置 → 提示词库 → 编辑通用规则”维护当前账号的联系方式、链接、事实和排版要求。固定改写、自动改写和文案试写会读取同一份规则；每套提示词只需填写风格和分类要求。保存后从下一次改写请求生效。

通用规则保存在现有 `system_settings` 表的 `ai_common_rewrite_rules` 键中，按账号隔离，不新增表或字段。未配置时使用内置通用规则；不可保存空内容。规则支持 `{{max_chars}}`、`{{rewrite_ratio}}`，只在请求合成时替换。

规则仅加入改写请求一次，不重复放入每个段落的分类提示词，也不加入第一轮分类分析请求。优先遵守模式自身的输出协议和改写比例；在共同保留要求下再应用分类风格。固定模式默认提示词依然是风格模板，不等同于通用规则。新账号和无模板兜底共用精简后的默认风格模板，已有其他账号的自定义模板不自动覆盖。

联系方式保留范围是基础清理后仍在 AI 输入中的内容。通用规则不会恢复任务清理步骤已经删除的信息，也不会替换为固定的联系号码。

本地商K多城市配置文件为 `docs/prompts/business-ktv-prompts.json`：六套提示词统一命名为“商K｜…”，各城市共用相应内容类型的规则。城市、区县、门店、价格与联系人按源文保留；没有城市信息时不根据频道或历史内容猜测补充。多城市或同名异地门店分别处理，不能跨城市混用费用、活动或联系人。

顶层 `common_rules` 仅一份，城市归属和联系方式保护在这里统一维护，六套 `prompts` 仅保存分类排版要求。建议改写比例是使用参考，实际比例由任务或试写表单决定。当前分类提示词按账号共享，没有单独的频道或城市作用域；“商K”是这套业务提示词的名称，不是新增的城市路由字段。配置中的示例来源频道仅作样本参考，不限制适用城市。

内置商品服务、优惠活动、通知公告、教程知识、故事观点、混合或未知六类规则。每类可以创建多套提示词，同类型采用当前用户最近保存且启用的一套；更新时间相同时采用较大的 ID。未配置启用的分类提示词时使用对应内置规则。没有设置适用类型的旧提示词仅参与固定选择。

自动匹配使用任务归属人的提示词和 AI 配置，不读取其他用户的内容。免费版的 AI 权限限制继续生效。

自动模式执行顺序：

基础过滤、替换及联系方式清理 → 分析源正文 → 按段落匹配分类提示词 → 改写与校验 → 追加原有 Head/Body/Footer 模板。

固定模式保持原顺序：基础处理 → 追加模板 → 固定提示词改写。

## 分析及校验

- 以空行分隔源段落，程序分配稳定编号；模型不能新增、遗漏或重复编号。分析中的 `layout_group` 以本组首段编号标记同一对象或主题，分组必须连续。
- 第一轮分析输出每段的类别、置信度、改写/保留动作和必须保留的原文事实片段。事实提取最小的名称、地址、数字及条件等片段，不把宣传形容、主观评价或整段话术全部锁为不可改写内容。
- 置信度低于 0.65 的段落使用“混合或未知”分类规则；分析请求失败或结果校验失败时，整条使用该分类规则继续改写，并记录回退状态。所有分类始终叠加同一份通用改写规则。
- 第二轮读取全文上下文及各段规则，正文仍按源编号分别返回并校验。保留段落由程序从原文回填，忽略模型对这些段的改动。
- `layout.order` 必须恰好覆盖全部源编号，只能在同一分组内调整顺序，不能交换或交错不同门店/主题。教程、故事及 0% 模式保持原顺序。`layout.separators` 指定相邻段之间使用一个或两个换行，让栏目标题与清单紧凑连接。缺少 layout 的旧响应继续按原顺序组装。
- 校验已提取事实片段、数字、联系方式、标签、链接、段落完整性和支持的 HTML 标签闭合情况。
- 自动模式不使用旧模式的随机轮换版式及版式相似度重试。
- 整理以保留原文大致内容为前提，主要调整分段、表情、列表和重点加粗，仅做必要的轻微润色。比例控制整理程度，不表示替换多少原文字数；即使 100% 也不重新创作内容。0% 仍执行排版请求，并校验正文措辞未改变。
- 自动模式认可排版、表情和 HTML 加粗等可见变化，不强制换词。完全相同、仅首尾空白/零宽字符或等效 HTML 标签变化不算成功。对于强度至少 35%、不少于 120 字且包含多个段落的商品/活动文案，还检查至少两处短标题加粗、两个区块用途表情和区块间留白，避免只加粗一处就通过；短文、低强度以及教程/故事不强套多区块样式。
- 无可见变化、版式未完成或保护校验未通过时，依据具体原因纠正试写一次，仍失败则沿用原失败策略。费用事实按“费用项目＋金额/单位”整体提取，程序另保护明确评分行中的符号。联系方式和标签显式列入各段保护清单。
- 试写区区分已处理、按规则保留、没有可见变化和处理失败，并显示具体分析回退原因；失败时不把原文显示为改写结果。分析明确全部保留时，显示原样保留原因。
- 输出失败、校验失败或超长时，按任务原有策略回退清洗后的原文或跳过。追加模板后超过现有 1024 字符安全长度，也进入失败策略，不静默截断 AI 结果。
- 语义层面的事实和分类仍依赖模型判断；这些检查不能保证模型对全部细节的理解正确，应先用真实样本试写。

源正文上限为 16000 字符、100 段；组合提示词上限为 120000 字符。通常执行分析和改写两次 AI 调用，发生纠正试写时最多三次；分析明确全部保留时不执行改写请求。每轮沿用现有请求超时设置。

提示词支持 `{{content}}`、`{{max_chars}}`、`{{rewrite_ratio}}`；自动模式另支持 `{{analysis}}`。占位符只替换一次，源文案不会被当成占位符模板继续展开。

## 数据迁移

新增字段：`clone_tasks.ai_prompt_mode`、`listener_tasks.ai_prompt_mode`（默认 `fixed`），以及 `ai_prompt_templates.content_type`（默认空）。不删除数据，不改动旧提示词内容，不自动启用任务。

后端启动时自动执行幂等迁移；对已存在的 SQLite 文件，使用 SQLite 在线备份接口生成完整备份后再添加字段。也可在后端运行目录手动执行：

```powershell
..\.venv\Scripts\python.exe migrate_ai_prompt_routing.py
```

必须使用实际运行服务的 `DATABASE_URL`。本次本地迁移文件为 `backend/data/clonebot.db`，备份为 `backend/data/clonebot.db.bak_ai_routing_20260911_180043_905144`。
