# 二维码媒体过滤

监听任务与克隆任务共用同一规则，通过任务现有的“过滤二维码图片”开关控制。

| 待发送内容 | 开启过滤后的行为 |
| --- | --- |
| 未检测到二维码 | 正常发送 |
| 图片与视频合计大于 2 个，且包含普通媒体 | 仅从发送列表移除二维码图片，保留其余媒体、顺序和说明文字 |
| 所有媒体都是二维码图片 | 整条消息过滤，即使带有文字说明也不单独发送 |
| 图片与视频合计不超过 2 个，且存在二维码 | 沿用整条过滤；“大于 2”不包含恰好 2 个 |
| 过滤开关关闭 | 保持原有完整媒体列表 |

数量按本条已准备发送的图片和视频合计计算，音频及普通文档不计入门槛。移除后只剩一个媒体时按单媒体发送。此规则过滤静态二维码图片，不扫描视频帧，也不修改源频道消息。

检测支持常用 JPG、JPEG、PNG、WebP、BMP 图片。图片按字节解码以支持 Windows 中文路径；二维码能被可靠定位但内容无法解码时仍可命中，并校验定位四边形，排除退化或非法坐标。

共享下载不会因某个任务过滤而改变，临时文件仍由原有清理流程统一处理。发送队列出口再次检查最新任务开关，避免等待期间配置变更使过滤失效。整条过滤记录过滤原因，队列内取消发送，不误记为发送失败或成功。

本次验证使用本地生成的二维码、遮挡二维码及普通图片，并模拟监听、克隆和发送队列；不向 Telegram 频道发送测试消息。
